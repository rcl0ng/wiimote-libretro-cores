FPS implementation

Wiimote motion uses consecutive absolute axis positions to generate relative
mouse packets. FPS packets bypass cursor-reference feedback and accumulated
relative-pointer backlog. Stationary input produces zero turn packets. Values
are capped at +/-63: Wolf3D treats bit 0x40 of mouse X as a bad serial read.
The first sample establishes an origin. Vertical IR movement is ignored.

Wolf3D USA: native hybrid interface. The ROM reads joystick JOY1 and mouse
JOY2. Frontend port 1 supplies both, internally mapped to the two SNES ports.
D-pad Left/Right becomes SNES L/R (strafe), X becomes Select (weapon), while
frontend Select is reserved for hotkeys. Native mouse buttons are released;
gamepad buttons handle fire/use. Motion comes from frontend port 1's left axes.

Doom USA: ROM's mouse conversion does not merge a second joystick. A guarded
word-write bridge supplies held action flags to the converted PlayerJoy input
word at WRAM 06f4. It is restricted to exact CRC 09e85ea6 and active FPS mode,
and accepts only WRAM/mirrored WRAM addresses. This is input-command blending,
not cursor-position feedback. PlayerMouseX/Y remain generated by the original
ROM's mouse conversion. D-pad Up/Down supplies relative mouse Y; Left/Right
supplies the stock strafe velocity and command flags. Run increases walking
packet magnitude. Button flags map to the ROM's native fire/use/weapon/pause.
This keeps simultaneous fire+use from becoming the mouse's both-button pause.

Doom's current upstream GSU cycle mode stalled the verified game after title;
legacy Snes9x GSU instruction-budget timing worked at 100%. v9 selects that
existing compatibility mode for this exact Doom CRC and resets the GSU at load.
Other ROMs keep the upstream timing selection.

Primary sources examined:
https://github.com/RandalLinden/DOOM-FX (source/rlplayer.a, rlplayer.i, rlplayer2.a)
https://github.com/lunarmeadow/idTech0-SNES (SOURCE/TEST.ASM, SNESMAIN.C,
  WOLFIO.C, PLMOVE.C; related Wolf3D/Super Noah engine release)
Related source behavior was verified against the supplied ROM's instructions
and real input words. No game data is included in this package.

Build/reproduce:
Linux: make -C libretro -j4 LTO=
Regression tests: python3 tests/run_analog_mouse_test.py
ROM-assisted tests require numpy, Pillow and the user's ROM:
PROBE_OPTIONS='{"snes9x_fps_hybrid":"automatic"}' python3 tests/rom_mouse_probe.py
  /path/to/Wolfenstein.sfc tests/rom_fps_scenario.py wolf
Use doom instead of wolf for the Doom ROM.
Windows: clean before changing platforms; build platform=win with MinGW x64,
LTO= and LDFLAGS=-static. DLL imports should be KERNEL32 and msvcrt only.
